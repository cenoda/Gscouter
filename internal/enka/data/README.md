# Enka data: legacy

These files map what an Enka.Network showcase carries (IDs, text map hashes, main stat values) to Gscouter's keys and names. They are **legacy data**, kept under the owner's legacy-data exception (2026-11-04, extended to Enka data on 2026-11-05; gscouter-engine `docs/independence.md` §4, "Enka data"). They are no longer regenerated from their sources: `gen.sh` and `gennames` write only into another directory, to diff against.

| File | What | Provenance |
|---|---|---|
| `character.dm.json` | Avatar ID (and the Traveler's skill depot) → gcsim key, element, icon, talent IDs | gcsim's UI data (`ui/packages/ui/src/data/`) at the fork go.mod pins, cenoda/gcsim `eb21884` (MIT license); byte-identical to it on 2026-11-05. gcsim builds it from Enka's store data, which is built from the game's files |
| `weapon.dm.json` | Weapon item ID → gcsim key, rarity, icon | As above |
| `artifact.dm.json` | Set name text map hash → gcsim key, icon | As above |
| `artifact_main_gen.json` | Artifact main stat values by rarity and level | As above; generated by gcsim from extracted data |
| `names.json` | In-game names in the game's 15 text languages | Enka.Network's store data (`EnkaNetwork/API-docs`, `store/gi/`, MIT license), read by `gennames`; last written 2026-10-29 (Gscouter `d537fd4`) |

Provenance of every entry in these files: `legacy_gcsim` (names: `legacy_enka_store`). An entry replaced or added by another source records it here.

## New IDs

New mappings are not taken from these sources. They are observed from the showcases Gscouter already receives: when a showcase carries an `avatarId` or a weapon `itemId` missing from these files, the server logs one line with the message `enka new id` (`observe.go`), once per distinct observation per process:

- a character: `avatar_id`, `skill_depot_id`, `level`, `ascension`, `base_hp`, `base_atk`, `base_def` (the showcase's `fightPropMap` 1, 4 and 7; `base_atk` includes the weapon's base ATK), `weapon_base_atk` (the weapon's shown base ATK, so the character's own is `base_atk − weapon_base_atk`);
- a weapon: `item_id`, `level`, `ascension`, `base_atk`, and its substat (`sub_prop`, `sub_value`) as the showcase shows them.

Nothing else is logged: no UID, nickname, other character or artifact. The ID is then matched to its key by those base stats against the official base stats (gscouter-engine `docs/independence.md` §4); the logged values are the source, recorded beside the new entry. The showcase is otherwise handled as before: a character or weapon not in the mapping is skipped, with the same reason.

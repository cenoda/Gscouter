# The key catalog

`catalog.json` is gscouter-engine's key catalog (its `docs/porting.md` §4): every character, weapon and artifact set the engine knows, by key, with the other names gcsl accepts for it. Gscouter takes its keys from it (`gamekeys.Char`, `Weapon`, `Set`) instead of gcsim's `pkg/shortcut` and `pkg/core/keys` (step 2 of the engine's `docs/independence.md`).

- **Engine commit**: `8a3c5800a4e6df3dc6f39bc5cf1c8e236f0ce06d` (gscouter-engine `main`, 2026-11-05), `gamekeys.EngineCommit`. The release Gscouter pins (`internal/engine/release`, `e6c8a07`) predates the catalog export (`1050c64`), so the catalog is taken from `main`. Only names and keys are read here; the engine's data and verification stay those of the pinned release. This is a snapshot: regenerate it from the release Gscouter pins once a release with the export is pinned.
- **How it was made**: this session could not build `gse`, so `catalog_fromsource.py` wrote it by reading the engine's own tables at that commit (`engine/src/data.rs` `CHAR_NAMES`, `CHAR_KEYS`, `WEAPON_NAMES`, `WEAPON_KEYS`, `SET_NAMES`, `SET_KEYS`, `CHARS`, `WEAPONS`; the content lists of `chars`, `weapons`, `sets`; the empty `provenance::RECORDS`), in the format of `engine/src/catalog.rs` `json()`. It is byte-identical to `gse --catalog` at that commit: the coordinator's run of `gse --catalog` at `8a3c580` gave the same 65,227 bytes, SHA-256 `df9ea364adb026f7570a8592b7bf33a1410d4fc676de043f1892264a13c45422` (2026-11-05). The script is a stopgap; later catalogs come from `gse --catalog`.
- **Updating**: `gse --catalog > internal/gamekeys/catalog.json` at the new engine commit, set `EngineCommit`, and run `go test ./internal/gamekeys ./internal/config ./internal/library`. A new name is added in the engine's `data.rs` only, never here.
- **Provenance**: every entry is `legacy_gcsim` (`provenance_default`): the names and keys were gcsim's `pkg/shortcut` tables at `eb21884`, kept under the owner's legacy-data exception of 2026-11-04.

The tests check that the catalog decodes, that it resolves exactly the names gcsim's `pkg/shortcut` accepts, each to the key gcsim prints (`TestSameAsGcsimShortcut`; it goes with the gcsim tests in step 5), and that it has every character, weapon and set the team library names (`TestCoversLibrary`).
